# Playbook de modelagem PostgreSQL

## Convenções obrigatórias

- usar nomes de tabelas no plural e `snake_case`
- usar chaves primárias `bigserial` ou `bigint generated by identity`
- usar timestamps com timezone para auditoria
- toda tabela operacional deve ter `created_at` e `updated_at`
- status e enums devem ser persistidos como `varchar`, nunca como ordinal
- valores monetários devem usar `numeric(15,2)`
- CNPJ, NSU, chave NF-e e códigos de eventos devem ser armazenados como texto

## Índices

- indexar colunas de busca frequente: `status`, `data_emissao`, `occurred_at`
- criar índices compostos para históricos ordenados por data decrescente
- indexar `lower(coluna)` para buscas textuais case-insensitive quando necessário

## Migrations

- usar Flyway em `backend/src/main/resources/db/migration`
- migrations devem ser incrementais e imutáveis
- toda mudança de esquema deve vir com revisão de índices e impacto em consultas
- não usar `ddl-auto` fora de ambiente de teste

## Relacionamentos

- usar `foreign keys` explícitas
- evitar cascatas destrutivas por padrão
- arquivos binários não devem ser gravados no banco; persistir apenas metadados e caminho seguro

## Storage

- XML e PDF devem ficar fora do banco
- organizar storage por `cnpj/ano/mes/chave`
- certificados A1 devem manter hash, tamanho, nome original e validade quando disponível

## Auditoria

- registrar histórico de mudança de status
- registrar logs de consulta à SEFAZ
- registrar auditoria de exportações
- nunca persistir senha do certificado em logs
